\section{Introduction}
% --------------------------------------------------
La seconde partie de ce TP s'inscrit dans une démarche d'assurance qualité et d'analyse statique de sécurité (SAST - \textit{Static Application Security Testing}). 

Après avoir développé l'application web Flask de gestion de projets et étudié l'injection SQL, nous avons intégré le projet à la plateforme **SonarCloud** (SonarQube) afin d'identifier les vulnérabilités de sécurité, les risques de sécurité (Security Hotspots), les failles d'accessibilité web (WCAG/a11y) et les problèmes de maintenabilité (Code Smells).

Ce compte rendu détaille le rapport d'analyse généré par Sonar, classe les anomalies détectées et propose les corrections appropriées pour chaque problème identifié.

% --------------------------------------------------
\section{Intégration de l'application à SonarCloud}
% --------------------------------------------------
L'intégration de l'application s'est déroulée en trois étapes principales :
\begin{enumerate}
    \item **Création du dépôt Git & GitHub :** Publication du code source nettoyé sur GitHub ;
    \item **Fichier de configuration Sonar :** Ajout du fichier \texttt{sonar-project.properties} à la racine du projet pour spécifier les paramètres d'analyse (version Python, exclusions) ;
    \item **Analyse automatique :** Exécution du scanner SonarCloud sur l'ensemble du projet.
\end{enumerate}

\section{Analyse détaillée et corrections proposées}
% --------------------------------------------------

\subsection{Problèmes de Sécurité (Security & Hotspots)}

\subsubsection{1. Risque CSRF (Cross-Site Request Forgery)}
\textbf{Alerte Sonar :} \texttt{Make sure disabling CSRF protection is safe here. (Security - High)}\\
\textbf{Explication :} L'application traite des requêtes HTTP POST sans utiliser de token anti-CSRF (comme \texttt{Flask-WTF}). Un attaquant pourrait forcer un utilisateur authentifié à soumettre des formulaires malveillants à son insu.\\
\textbf{Correction :} Intégrer la protection CSRF globale avec l'extension \texttt{Flask-WTF} ou inclure un token CSRF dans les formulaires POST.

\subsubsection{2. Mot de passe en dur (Hardcoded Credentials)}
\textbf{Alerte Sonar :} \texttt{"password" detected here, review this potentially hard-coded credential. (database.py)}\\
\textbf{Explication :} Une valeur de repli par défaut pour le mot de passe de la base de données est directement écrite dans le code Python.\\
\textbf{Correction :} Supprimer la valeur par défaut en dur et forcer la lecture exclusive via les variables d'environnement (\texttt{os.getenv}).

\subsubsection{3. Mode Debug activé}
\textbf{Alerte Sonar :} \texttt{Make sure this debug feature is deactivated before delivering the code in production. (app.py)}\\
\textbf{Explication :} \texttt{app.run(debug=True)} expose le debugger interactif Werkzeug, permettant l'exécution arbitraire de code en cas d'erreur uncaught.\\
\textbf{Correction :} Dépenser le paramètre `debug` d'une variable d'environnement \texttt{FLASK_DEBUG=False} en production.

\subsubsection{4. Subresource Integrity (SRI) manquant sur les CDN}
\textbf{Alerte Sonar :} \texttt{Add integrity and crossorigin="anonymous" attributes to this element. (templates/layout.html)}\\
\textbf{Explication :} L'inclusion des scripts et styles Bootstrap externes depuis un CDN sans attribut \texttt{integrity} présente un risque de sécurité si le CDN est compromis.\\
\textbf{Correction :} Ajouter les empreintes de hachage (hashes SHA-384) sur les balises \texttt{<link>} et \texttt{<script>}.

\subsection{Problèmes d'Accessibilité Web (WCAG 2.0 / a11y)}

\textbf{Alerte Sonar :} \texttt{Add an "id" attribute to this input field and associate it with a label. (nouveau.html)}\\
\textbf{Explication :} Dans le formulaire de création d'affectation, les balises \texttt{<label>} ne possèdent pas d'attribut \texttt{for="..."} pointant vers l'attribut \texttt{id="..."} du champ de saisie correspondant. Cela pénalise les lecteurs d'écran pour les personnes malvoyantes.\\
\textbf{Correction :} Associer explicitement chaque label au champ correspondant :
\begin{lstlisting}[language=HTML, caption=Correction de l'accessibilité dans le formulaire]
<!-- Avant -->
<label class="form-label">Nom du Projet</label>
<input type="text" class="form-control" name="nomProj">

<!-- Après (Conforme WCAG) -->
<label for="nomProj" class="form-label">Nom du Projet</label>
<input type="text" id="nomProj" class="form-control" name="nomProj">
\end{lstlisting}

\subsection{Problèmes de Maintenabilité et Conventions (Code Smells)}

\subsubsection{1. Méthodes HTTP non spécifiées sur les routes}
\textbf{Alerte Sonar :} \texttt{Specify the HTTP methods this route should accept. (app.py)}\\
\textbf{Explication :} Par défaut, \texttt{@app.route('/')} accepte uniquement la méthode GET, mais il est recommandé de spécifier explicitement \texttt{methods=["GET"]} pour améliorer la lisibilité du code.

\subsubsection{2. Conventions de nommage Python (snake\_case vs camelCase)}
\textbf{Alerte Sonar :} \texttt{Rename this local variable "nomProj" to match the regular expression \string^[\_a-z][a-z0-9\_]*\$. (app.py)}\\
\textbf{Explication :} En Python (norme PEP 8), les variables locales doivent être nommées en \texttt{snake\_case} (\texttt{nom\_proj}) et non en \texttt{camelCase} (\texttt{nomProj}).

\section{Solutions et Plan de Remédiation Détaillé}
% --------------------------------------------------
Cette section présente le plan de remédiation complet avec le code source corrigé pour chacune des vulnérabilités, failles d'accessibilité et code smells relevés par SonarCloud.

\subsection{1. Protection contre les attaques CSRF (Sécurité - Sévérité Élevée)}
\textbf{Problème :} L'application traite des formulaires soumis via la méthode HTTP POST sans validation de jetons d'authenticité anti-CSRF.

\textbf{Code Corrigé (\texttt{app.py}) :}
\begin{lstlisting}[language=Python, caption=Mise en place de Flask-WTF / CSRFProtect]
from flask import Flask
from flask_wtf.csrf import CSRFProtect

app = Flask(__name__)
app.config["SECRET_KEY"] = os.getenv("SECRET_KEY")

# Activation globale de la protection CSRF
csrf = CSRFProtect(app)
\end{lstlisting}

\textbf{Dans le formulaire HTML (\texttt{templates/nouveau.html}) :}
\begin{lstlisting}[language=HTML, caption=Ajout du champ token CSRF caché]
<form method="POST" action="{{ url_for('nouvelle_affectation') }}">
    <!-- Token CSRF dynamique généré par Flask-WTF -->
    <input type="hidden" name="csrf_token" value="{{ csrf_token() }}"/>
    ...
</form>
\end{lstlisting}

\subsection{2. Élimination des identifiants en dur (Security Hotspot)}
\textbf{Problème :} L'utilisation de valeurs de mots de passe par défaut dans la fonction de connexion risque d'exposer des identifiants de production en cas de fuite du code source.

\textbf{Code Corrigé (\texttt{database.py}) :}
\begin{lstlisting}[language=Python, caption=Suppression des identifiants par défaut]
# Lève une exception explicite si les variables d'environnement ne sont pas définies
DB_HOST = os.environ.get("DB_HOST", "localhost")
DB_PORT = os.environ.get("DB_PORT", "5432")
DB_NAME = os.environ.get("DB_NAME", "gestion_projets")
DB_USER = os.environ.get("DB_USER")
DB_PASSWORD = os.environ.get("DB_PASSWORD") # Aucune valeur par défaut en dur !
\end{lstlisting}

\subsection{3. Désactivation du Mode Debug en Production (Sécurité - Sévérité Faible)}
\textbf{Problème :} L'instruction \texttt{app.run(debug=True)} expose le shell d'exécution interactif en cas d'erreur.

\textbf{Code Corrigé (\texttt{app.py}) :}
\begin{lstlisting}[language=Python, caption=Contrôle du mode debug via variable d'environnement]
if __name__ == "__main__":
    # Désactivé par défaut en production
    is_debug = os.getenv("FLASK_DEBUG", "false").lower() in ("true", "1")
    app.run(debug=is_debug, host="127.0.0.1", port=5000)
\end{lstlisting}

\subsection{4. Intégrité des Ressources CDN (Subresource Integrity - SRI)}
\textbf{Problème :} L'importation de Bootstrap via un CDN externe sans validation d'empreinte numérique permettrait l'exécution de scripts malveillants si le serveur CDN était altéré.

\textbf{Code Corrigé (\texttt{templates/layout.html}) :}
\begin{lstlisting}[language=HTML, caption=Ajout des attributs integrity et crossorigin]
<!-- Feuille de style CSS avec contrôle d'intégrité -->
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.2/dist/css/bootstrap.min.css" 
      rel="stylesheet" 
      integrity="sha384-T3c6CoIi6uLrA9TneNEoa7RxnatzjcDSCmG1MXxSR1GAsXEV/Dwwykc2MPK8M2HN" 
      crossorigin="anonymous">

<!-- Script JS avec contrôle d'intégrité -->
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.2/dist/js/bootstrap.bundle.min.js" 
        integrity="sha384-C6RzsynM9kWDrMNeT87bh95OGNyZPhcTNXj1NW7RuBCsyN/o0jlpcV8Qyq46cDfL" 
        crossorigin="anonymous"></script>
\end{lstlisting}

\subsection{5. Correction des Formulaires d'Accessibilité Web (WCAG 2.0 / a11y)}
\textbf{Problème :} Les étiquettes \texttt{<label>} ne sont pas reliées aux champs de saisie \texttt{<input>}, empêchant la lecture par les technologies d'assistance pour personnes malvoyantes.

\textbf{Code Corrigé (\texttt{templates/nouveau.html}) :}
\begin{lstlisting}[language=HTML, caption=Association explicite for / id conforme WCAG 2.0]
<div class="col-md-6">
    <label for="nomProj" class="form-label fw-semibold">Nom du Projet *</label>
    <input type="text" id="nomProj" class="form-control" name="nomProj" placeholder="ex: ILO" required>
</div>
<div class="col-md-6">
    <label for="mgrProj" class="form-label fw-semibold">Manager du Projet *</label>
    <input type="text" id="mgrProj" class="form-control" name="mgrProj" placeholder="ex: Dupont" required>
</div>
<div class="col-md-4">
    <label for="idEmp" class="form-label fw-semibold">ID Employé *</label>
    <input type="text" id="idEmp" class="form-control" name="idEmp" placeholder="ex: E101" required>
</div>
\end{lstlisting}

\subsection{6. Explicitation des Méthodes HTTP sur les Routes Flask}
\textbf{Problème :} Omettre le paramètre \texttt{methods} nuit à la lisibilité et au principe de moindre privilège.

\textbf{Code Corrigé (\texttt{app.py}) :}
\begin{lstlisting}[language=Python, caption=Spécification explicite des verbes HTTP]
@app.route("/", methods=["GET"])
def index():
    ...

@app.route("/projet/<string:nom_proj>", methods=["GET"])
def projet_detail(nom_proj):
    ...
\end{lstlisting}

\subsection{7. Conformité aux Conventions de Nommage Python (PEP 8)}
\textbf{Problème :} L'utilisation du style \texttt{camelCase} pour les variables locales enfreint le standard PEP 8 recommandé par SonarCloud (\texttt{snake\_case}).

\textbf{Code Corrigé (\texttt{app.py}) :}
\begin{lstlisting}[language=Python, caption=Refactorisation du nommage des variables en snake_case]
# Avant : nomProj, mgrProj, idEmp, nomEmp, salEmp, evalEmp
# Après (PEP 8) :
nom_proj = request.form.get("nomProj", "").strip()
mgr_proj = request.form.get("mgrProj", "").strip()
id_emp = request.form.get("idEmp", "").strip()
nom_emp = request.form.get("nomEmp", "").strip()
sal_emp = float(request.form.get("salEmp", 0))
eval_emp = int(eval_emp_raw) if eval_emp_raw else None
\end{lstlisting}

\section{Analyse Complémentaire par l'Intelligence Artificielle (Gemini 3.6 Flash)}
% --------------------------------------------------
En complément de l'analyse statique automatisée effectuée par SonarCloud, une révision de code approfondie a été réalisée par l'Agent d’Intelligence Artificielle **Gemini 3.6 Flash** (GitHub Copilot).

L'objectif de cette double approche est de comparer l'analyse SAST traditionnelle basée sur des règles déterministes (Sonar) avec une analyse sémantique guidée par un modèle de langage (IA LLM).

\subsection{Problèmes Critiques et Avancés Identifiés par l'IA Gemini}

Alors que SonarCloud se concentre principalement sur les erreurs de syntaxe, d'accessibilité et de configuration, l'analyse par l'IA Gemini a permis de révéler des risques d'architecture, de logique métier et de sécurité des données plus subtils :

\subsubsection{1. Absence de Gestion Transactionnelle lors des Opérations Multi-Requêtes}
\textbf{Analyse Gemini :} Dans \texttt{init_db.py} et \texttt{app.py}, en cas d'échec lors d'une insertion intermédiaire ou d'une erreur d'unicité (\texttt{UNIQUE constraint failed}), l'absence de bloc d'exception avec \texttt{conn.rollback()} explicite peut laisser la base de données SQLite ou PostgreSQL dans un état incohérent ou verrouillé.

\textbf{Correction proposée par l'IA :}
\begin{lstlisting}[language=Python, caption=Gestion robuste des transactions avec try/except/rollback]
try:
    cursor.execute(insert_sql, (nom_proj, mgr_proj, ...))
    conn.commit()
except Exception as err:
    conn.rollback() # Annulation propre de la transaction
    flash(f"Erreur d'insertion en base de donnees : {err}", "danger")
finally:
    cursor.close()
    conn.close()
\end{lstlisting}

\subsubsection{2. Exposition de Données Sensibles (Salaires et Évaluations)}
\textbf{Analyse Gemini :} Sur la vue générale (\texttt{index.html}), la colonne \texttt{salEmp} (salaire annuel de l'employé) et \texttt{evalEmp} (évaluation individuelle) sont affichées publiquement à tous les utilisateurs. D'un point de vue de la confidentialité des données (RGPD / Politique RH), ces attributs ne devraient être visibles que par le manager du département ou l'employé concerné.

\textbf{Recommandation de l'IA :} Masquer ou restreindre l'affichage des colonnes sensibles selon le rôle de l'utilisateur authentifié.

\subsubsection{3. Échappement des Métacaractères LIKE (\% et \_)}
\textbf{Analyse Gemini :} Même en utilisant des requêtes paramétrées (\texttt{WHERE nomProj LIKE ?}), si l'utilisateur recherche un symbole littéral \texttt{\%} ou \texttt{\_}, le SGBD les interprète comme des jokers SQL. Un utilisateur peut ainsi lister l'ensemble des enregistrements en saisissant simplement le caractère \texttt{\%}.

\textbf{Correction proposée par l'IA :}
\begin{lstlisting}[language=Python, caption=Neutralisation des métacaractères LIKE par l'IA]
def escape_like(text):
    # Echappe les caracteres speciaux du prédicat LIKE
    return text.replace("\\", "\\\\").replace("%", "\\%").replace("_", "\\_")

search_term = f"%{escape_like(query_search)}%"
\end{lstlisting}

\subsubsection{4. Validation de Type et Assainissement des Entrées (Input Sanitization)}
\textbf{Analyse Gemini :} Les valeurs saisies dans le formulaire (comme le budget, le salaire ou les heures) sont converties directement sans validation préalable de plage de valeurs (ex: budget négatif ou nombre d'heures > 168h/semaine).

\section{Conclusion}
% --------------------------------------------------
L'intégration de SonarCloud a permis d'évaluer la qualité du code sous plusieurs angles complémentaires à la sécurité brute. Si la première partie du TP s'est focalisée sur la détection et la prévention des injections SQL, cette deuxième partie met en évidence l'importance d'une analyse automatisée continue (SAST).

Les retours fournis par SonarCloud permettent de traiter de manière préventive des vulnérabilités secondaires (CSRF, SRI), des failles d'accessibilité (WCAG) ainsi que des défauts de maintenabilité, garantissant ainsi un code web propre, accessible et sécurisé.
